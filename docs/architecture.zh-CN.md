# 架构说明

[返回项目首页](../README.zh-CN.md)

JEV MLX 0.1 从应用提供的有限候选集中做出选择。模型路径负责语义评分，执行路径由明确的宿主应用代码负责。模型预测、执行授权和执行回执始终分开。

## 公共数据契约

`Candidate(id, description, value=None)` 包含稳定的业务 ID、语义描述和可选的 JSON 值。`DecisionRequest` 包含 JSON 状态、用户话语、候选、非负的 `state_version`、问题，以及 `kind="enum"` 或 `kind="boolean"`。严格的 `from_dict` 和 `to_dict` 转换支持外部客户端。应用候选列表可以为空：no-match 和 abstain 仍然可选。

候选 ID 必须唯一，不能使用 `__no_match__` 或 `__abstain__`。JSON 对象的键必须是字符串，数值必须有限。输入会在验证以及推理／会话边界复制。冻结字段并不会让嵌套 JSON 对象天然不可变；调用方应把它们当作值来使用。会话还会为发出的结果计算指纹，在执行前拒绝被修改的结果。

| 限制项 | 默认值 |
|---|---|
| 应用候选 | 64 个，另加两个保留结果 |
| 候选 ID／描述 | 128 / 2,048 个字符 |
| 候选 JSON 值 | 16,384 个 UTF-8 字节 |
| 状态 JSON | 131,072 个 UTF-8 字节；最多嵌套 16 层 |
| 用户话语／问题 | 16,384 / 2,048 个字符 |
| 分词后的提示词 | 4,096 token |
| 预填充分块 | 256 token |
| 前缀缓存 | 512 MiB，最多 16 条 |
| 待执行的会话授权 | 最近 256 个选中结果 |

后端的提示词、预填充和缓存上限可通过 `MLXDecisionEngine(model, **backend_options)` 配置。这些是资源限制，不是对模型上下文长度的保证。即使请求低于这些上限，token 编码可用性检查与聊天模板验证仍可能拒绝它。

## 本地模型路径

`MLXDecisionEngine` 只在构造真实模型引擎时延迟导入 MLX。数据契约、会话以及注入后端的测试无需 MLX 即可使用。`MLXLMBackend` 要求本地目录包含 `config.json`，并调用官方 `mlx_lm.load`，设置 `trust_remote_code=False`。它既不下载也不修改权重。

`prompt.py` 将状态、问题、候选描述／值以及用户话语序列化到检查点的聊天模板中。其策略描述了否定、不存在的目标、可见顺序、状态询问与歧义的处理。这是给模型的指令，而非针对特定语句的规则引擎。布尔模式回答所提供的事实问题：`False` 是一个选中的有类型值；证据不足时可以选择弃权。

编译器搜索数字和 ASCII 编码，验证其单 token 编码的唯一性与编码／解码往返一致性，并检查完整提示词后的单 token 续写。编码仅用于内部：候选重排可能改变编码，业务 ID 则保持稳定。可见顺序由明确的状态提供给模型理解；不会用候选顺序替代 UI 顺序。

预填充后，后端针对最终输入位置调用官方模型，从未经修改的输出头中索引候选 logits；模型有量化输出头时也完整保留。它不会用切片后的权重矩阵替换输出头。直接决策不使用生成的后续文本。该方法仍然使用因果语言模型的下一个 token 分布；它并不构成新的非自回归架构，也没有复现 JEV 训练。

## 结果语义与计时

引擎检查当前候选与保留结果的分数是否齐全且为有限值，计算数值稳定的受限 softmax 分数，并报告最大两个原始 logits 之间的差值。这些分数不是经过校准的正确概率。默认的 `margin_threshold=0.0` 会拒绝最高分完全相等的情况。正阈值可以拒绝分差较小的结果；`raw_selected_id` 保留原始胜出候选。

| 状态 | 含义 | 可执行 ID |
|---|---|---|
| `selected` | 一个应用提供的候选胜出 | `candidate_id` |
| `no_match` | 没有适用的请求动作或答案 | `None` |
| `abstain` | 存在歧义、证据不足或未达到分差阈值 | `None` |
| `stale` | 推理期间会话状态发生变化 | `None` |

`selected_value` 复制所选候选的 JSON 值，未选中候选时为 `None`。被选中的候选本身也可能以 `None` 为值，因此应检查 `status`。元数据包括版本、请求 ID、模型／配置／分词器身份、依赖、量化、缓存类型、耗时以及缓存复用情况。它不是完整的权重文件指纹；还应保留检查点来源记录。

MLX 延迟调度计算。后端会求值 logits 与全部缓存状态，并在测量已完成的推理前同步。后端计时区分排队等待、推理和加载。引擎的 `decision_ms` 测量其评分与编排区间；HTTP 往返时间还包含传输与浏览器工作。内存峰值是进程生命周期内的峰值，不是单次决策的分配量。

## 稳定前缀快照

实现复用了官方 `make_prompt_cache` 和 `LRUPromptCache`；参见[框架审查](framework-audit.zh-CN.md)。缓存命名空间隔离会话与输出模式；系统快照和页面快照再使用独立命名空间，共享同一个 LRU 容量上限。实际 token 序列用于识别可复用内容。状态版本是宿主元数据，不是答案缓存的键。

两个完整快照边界很重要：

1. 可变页面内容之前。
2. 稳定状态与候选之后、当前用户话语之前。

分词器可能跨越名义上的文本边界合并内容。构建器只保留与完整编码后提示词完全相同的 token 前缀，不假设文本偏移就是安全的缓存边界。

同一页面的新话语可以复用第二个快照，但必须计算新的后缀。状态、候选或问题变化会使其依赖的后缀失效；这时只能复用保存的完整系统快照。SDK 丢弃在中间位置裁剪得到的最近缓存匹配，纯注意力模型也不例外。这使预填充边界与全新调用保持一致；此前 GLM 的数值验证失败和后续验证均记录在[结果报告](results.zh-CN.md)中。Qwen3.5 等混合模型除了注意力 KV，还包含循环／卷积状态。较早位置的完整快照同时保存两者。实现不会像 KV 一样回滚循环状态，不会在保留后续状态的同时替换中间前缀，也不会为独立问题自创注意力掩码。

`session.prewarm()` 只计算稳定前缀状态，并报告捕获的版本、当前版本，以及 `ready` 或 `stale`。它不发出决策或执行授权。缓存淘汰可能导致后续请求未命中。最终答案永不缓存。真实的数值与选中动作一致性必须通过实际模型运行验证；容差和结果见[评测说明](evaluation.zh-CN.md)与[结果报告](results.zh-CN.md)。

## 状态与执行生命周期

`DecisionSession.decide` 在锁内保存状态／候选快照，推理期间释放锁，之后重新检查捕获的版本。`update_state` 原子替换状态与可选的候选，递增版本，并使待执行动作的授权失效。应用必须在每次与有效性相关的变化时调用它，包括手动点击、加载中／就绪状态切换。

`execute(result, callback)` 要求结果对象由本会话发出且完整、状态为已选中候选、版本为当前版本、请求 ID 未被消费。它在运行应用代码前消费授权，并在回调期间持续持有状态锁。回调失败不能自动重放已产生部分效果的操作。回调可重入更新状态。如果宿主还有另一把状态锁，应始终先获取宿主锁，再获取会话锁。

`StaleDecisionError`、`ReplayDecisionError` 和 `InvalidDecisionError` 均继承自 `DecisionExecutionError`。回调返回应用执行回执。通过这些检查只说明动作属于当前状态且由本会话发出，不代表语义正确。HTTP 客户端接收不透明票据，对应保存在服务器上的结果；将结果 JSON 反序列化不能重新创建执行授权。

## 浏览器与服务边界

localhost 服务提供随包分发的 Morrow Studio 静态资源与 HTTP API。桌面和课程均为虚构。演示根据当前视图、筛选条件、排序和播放器就绪状态派生允许动作。选中的 ID 转换为针对已有 `data-action` 控件的白名单点击操作。浏览器代码带着服务器发出的票据，调用该控件的真实点击处理函数。服务器在应用状态转换前验证并消费票据。手动控件使用同一个状态机，并使待处理决策失效。

UI 分别展示模型决策、浏览器事件和服务器执行回执。模拟播放器不解码真实视频。模型不接收截图，不定位任意 DOM 目标，不生成 JavaScript，也不操作无关网站。请求格式与本地服务限制见 [HTTP 与演示文档](http-and-demo.zh-CN.md)。

## 暂缓的工作

后端串行处理调用并使用现有检查点。GPU 批处理、多步规划、通用聊天、STT、任意工具参数、新模型训练，以及通用检查点兼容性均不在 0.1 范围内。后续并行推理应复用官方批处理／缓存能力，在宣称支持前验证混合状态与数值一致性。
