# MLXJ 方块游戏

[返回首页](../README.zh-CN.md)

MLXJ Blocks 是一个由本地模型选择方块落点的游戏。每次选择都能在棋盘上直接看到：
方块逐渐堆叠，填满的行被消除，不好的连续选择也可能导致游戏结束。
这是原创的简化规则实现，不是官方俄罗斯方块产品，也不实现竞技俄罗斯方块的完整规则。
本演示没有复制第三方游戏代码。

## 本地运行

按照[快速开始](../README.zh-CN.md#quick-start)在项目独立环境中安装 MLXJ，
然后使用已有的兼容本地模型启动服务：

```sh
jev-mlx serve --model /absolute/path/to/local/checkpoint --port 8765
```

打开 [MLXJ 方块游戏](http://127.0.0.1:8765/blocks)。可以启动本地模型连续游玩、
只请求一次落点选择、暂停、重置或手动游玩。这些模式使用相同的棋盘规则。
手动游玩不需要推理；新的模型决策需要本地 MLX 服务，不涉及云端 API 或 API 密钥。

HTML、JavaScript 和手动游戏可以通过静态文件服务运行。发布这些文件或录屏，
**不会**让模型在 GitHub Pages 或访问者浏览器中运行。
模型运行在提供本地回环服务的 Mac 上，由 Python 进程执行推理。

## 模型实际选择什么

每一轮，浏览器提供结构化的 10 × 20 棋盘、当前方块，以及所有当前合法的垂直下落落点。
这里的落点指先在棋盘上方旋转方块，再垂直下落可以到达的位置；
需要在下落途中横向滑入悬空结构下方的位置，不属于这套简化动作空间。

每个候选包含规则代码计算的事实，例如消除行数、落子后的最大堆叠高度和空洞数。
这是结构化信息，不是视觉识别：模型不接收截图。规则代码不对落点排名，也不选择最优动作。
它只提供候选，由 MLXJ 使用配置的本地模型为候选的单 token 编码评分。

选中的候选同时确定旋转方向和落点列。旋转、下落、碰撞检查、消行、计分和绘制都由游戏代码执行。
模型不控制每一帧动画，而是**每个方块决策一次**，棋盘等待这次决策完成。
动画效果不能用来证明模型具备某种实时反应速度。

不匹配、弃权和配置的分数间隔阈值仍然生效。决策被拒绝或发生错误时，不会偷偷改用规则算法落子，
也不会自动重试来获取更好的答案。候选分数不是经过校准的“下对概率”。

## 查看实际发生的事情

页面展示分数、消行数、选中的落点和实测决策耗时。
详细记录将完整模型响应与实际执行回执分开，包含状态版本、候选分数、分数间隔、
模型身份、耗时和缓存信息。可以下载记录，检查整段过程。

推理尚未返回时，如果发生重置、手动移动或其他相关状态变化，旧决策会失效。
浏览器执行前会检查当前状态版本和候选是否合法。执行保护拦住一个模型输出，
不代表模型原本选择正确。

前缀缓存复用符合条件的模型状态，不缓存最终动作。
每次落子后棋盘都会变化，因此不能假装页面未变，继续使用依赖旧棋盘的缓存。
结果中的缓存信息说明实际复用了什么。

## 复现与检查

确定性游戏规则检查不需要加载模型：

```sh
node --test tests/blocks-engine.test.mjs
```

录制真实本地模型运行时，先在项目环境中安装可选浏览器依赖和 Chromium，并保持 MLX 服务运行：

```sh
python -m pip install -e '.[mlx,browser]'
PLAYWRIGHT_BROWSERS_PATH=.cache/playwright python -m playwright install chromium --only-shell
```

在另一个终端中，用隔离的浏览器上下文录制固定种子的运行：

```sh
PLAYWRIGHT_BROWSERS_PATH=.cache/playwright .venv/bin/python examples/record_blocks.py \
  --url http://127.0.0.1:8765/blocks \
  --pieces 20 --seed 42 \
  --output output/playwright-blocks/run-42
```

每次使用新的输出目录。失败、拒绝和执行错误都应与成功运行一并保留。
固定种子可复现方块序列，不保证不同硬件或依赖版本下的模型分数完全一致。

## 当前范围

游戏能力仍属实验性质，尚未通过冻结的游戏测试集评估。
一段录屏只能证明这次运行确实发生，不能证明模型下得好、速度更快或具备通用规划能力。
已有的[评测结果](results.zh-CN.md)衡量语义动作选择，不能作为方块游戏成绩。

本演示向模型提供合法落点及其即时后果，并不能证明截图理解、多步搜索、逐帧控制或任意网页操作能力。
这个小游戏的用途，是让本地动作选择更容易观察和测试。
