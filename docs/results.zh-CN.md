准备调用异常。66 次无效 JSON 输出仍属于

## 三种缓存条件下的历史延迟

数值为外层墙钟时间，单位毫秒，包含已经完成并同步的
MLX 计算及请求／结果调度，不包含模型加载。准备
调用单独记录，不计入测量的决策时间区间。
每个单元格为 **p50 / p95**，每格对应 28 次调用。

| 方法 | 权重已加载、KV 冷 | 同页新话语 | 页面更新后的首次决策 |
|---|---:|---:|---:|
| 直接评分 | 2,447.5 / 3,751.7 | 196.3 / 202.7 | 1,196.3 / 1,678.9 |
| 单编号生成 | 2,794.7 / 3,243.2 | 445.4 / 693.9 | 1,490.0 / 2,248.8 |
| 原始业务 ID JSON | 2,833.8 / 3,524.2 | 604.3 / 1,304.8 | 1,662.2 / 2,603.5 |
| 补充 JSON 编号，受测试结果启发 | 2,666.6 / 4,271.9 | 529.4 / 953.6 | 1,615.9 / 2,834.7 |

与单编号生成相比，直接评分的 p50 在 KV 冷时约快 1.14×，
同页复用时约快 2.27×，页面更新后约快 1.25×。直接评分的 KV 冷 p95
**更慢**，最终返回的可执行覆盖率也更低。这体现的是
质量与延迟之间不同的取舍，不能据此声称全面占优。
这些 p50 数值均未达到固定 100 ms 的性能目标。

单编号基线使用官方 `stream_generate(max_tokens=1)`；该
流程可能调度下一步预取计算，同步计时将其包含在内。
直接评分读取最后位置的 logits，不生成后续文本。
基于相同官方模型优化后的单步 argmax 可以复用这种直接
计算。因此，测得的差异不能证明拥有独家
算法、新模型架构、优于一切单编号
实现，或复现了 JEV 未公开的方法。

输入规模为 2–6 个应用候选，加两个保留结果；话语
长度为 8–34 个字符，序列化状态长度为 65–336 个字符。直接评分／编号
提示词为 478–623 tokens；原始 JSON 为 495–640，补充 JSON
编号为 500–645。直接评分同页热缓存调用复用 465–607 tokens，重新计算
13–18 tokens。页面更新调用复用 300-token 的稳定系统前缀，
重新计算 178–323 tokens。没有复用已完成的答案。主实验保留了
168 条独立准备记录；补充实验保留了 56 条。

## 第二个检查点：GLM-4.7-Flash-4bit

GLM 成功加载并产生了真实本地输出，但**能够加载不代表
它在当前提示词下可以用作通用直接选择模型**。其直接评分
准确率为 14/28（50.0%），有两个错误动作，即使同页热缓存 p50 为
191.4 ms。保留这个负面结果是模型对照的一部分。

检查点版本为 `1454cffb1a21737e162f508e5bc70be9def89276`，架构
为 `glm4_moe_lite`，采用 affine 4-bit 量化、group size 64，以及官方
`KVCache`。硬件和依赖版本与 Qwen 实验相同。其
[元数据](../benchmarks/results/glm-test/metadata.json)记录了实现
及检查点身份。没有为 GLM 调整语义提示词或阈值。
